# 拙政园智能导览（RAG）

面向游客的拙政园问答：景点介绍、门票/开放时间、游览路线、最佳赏花季节；支持上传照片识别景点。回答带 `[n]` 引用，可展开查看原文片段。

- 对话与识图：`deepseek-flash`（OpenAI 兼容接口，支持图片输入）
- Embedding：OpenAI 兼容接口（默认示例为硅基流动 `BAAI/bge-m3`）；未配置时自动退化为纯 BM25
- 后端：FastAPI + SSE 流式；前端：单页 HTML（无构建）
- 线上地址：`<部署后填写>`

## 快速开始

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # 填入 LLM_API_KEY（以及可选的 EMBED_API_KEY）
.venv/bin/python -m app.ingest   # 构建索引（服务首次启动时也会自动构建）
.venv/bin/uvicorn app.main:app --port 8000   # 打开 http://localhost:8000
.venv/bin/python -m eval.run_eval            # 检索评测
```

## 1. 整体架构

```
 数据层                    索引层                          在线链路
┌────────────┐   清洗     ┌──────────────────┐      ┌──────────────────────────────────────┐
│ data/*.md  │──────────▶ │ 按标题层级+句子切块 │      │ 游客问题 [+ 照片]                      │
│ (带来源/时效 │  front     │ 块首加标题路径      │      │   │ 照片 → deepseek-flash 识图（候选景点   │
│  元数据)    │  matter    │ 【拙政园/中部/远香堂】│      │   │         约束输出 JSON）→ 并入问题     │
│ aliases.json│           └───────┬──────────┘      │   ▼                                  │
└────────────┘                   │                  │ 多轮指代改写（有历史时调用 LLM）          │
                         ┌───────┴────────┐         │   ▼                                  │
                         │ BM25(jieba+领域词典)│◀──────│ 别名扩展（廊桥→小飞虹）                  │
                         │ 向量(bge-m3)     │         │   ▼                                  │
                         └───────┬────────┘         │ BM25 ∥ 向量 → RRF 融合 → 实体加权       │
                                 └─────────────────▶│   ▼                                  │
                                                    │ 相关性门限（不相关 → 直接拒答，不调用 LLM） │
                                                    │   ▼                                  │
                                                    │ 带编号资料 + 约束 prompt → 流式生成+引用   │
                                                    └──────────────────────────────────────┘
```

目录：`app/ingest.py` 入库，`app/retriever.py` 检索，`app/rag.py` 主链路，`app/llm.py` 模型调用，`app/main.py` 接口，`eval/` 评测。

## 2. 核心难点与解决方案

| 难点 | 做法 | 位置 |
|---|---|---|
| **切块后丢失主语**：“它建于哪年”切到后面，块里没有“远香堂” | 按 Markdown 标题层级切分，每块前缀标题路径 `【拙政园 / 中部景区 / 远香堂】`，同时参与 BM25 与向量；块间保留 1 句重叠 | `ingest.py` |
| **专有名词分词**：“卅六鸳鸯馆”“与谁同坐轩”被 jieba 切碎，BM25 失效 | 景点名与别名全部注入 jieba 词典 | `retriever.py` |
| **口语/别名与书面语不一致**：游客说“廊桥”“石舫”“蓝玻璃那个厅” | `aliases.json` 别名表做查询扩展（补上标准名）；向量检索兜底语义近似 | `retriever.py` |
| **召回准确性**：纯向量对“门票多少钱”“几点关门”这类关键词强的问题不稳，纯 BM25 对口语改写不稳 | BM25 + 向量双路召回，RRF 融合（免调权重），命中景点实体的块额外加权 | `retriever.py` |
| **多轮指代**：“它为什么叫这个名字” | 有历史时用 LLM 改写成独立问句，再检索；改写失败回退原问题 | `rag.py` |
| **幻觉 / 超范围问题**：问天气、问代码、问资料没有的内容 | ①相关性门限：两路都不相关则直接拒答（不调 LLM，省钱）；②prompt 约束“只依据资料，缺失就说没有”；③强制 `[n]` 引用 | `retriever.py` `rag.py` |
| **时效信息**：票价、开放时间会变，旧资料里还有 50/90 元等过期价格 | 数据带 `volatile` / `updated` 元数据，进入 prompt 时标“时效信息 + 更新日期”，要求回答末尾提示以官方为准；资料内如实写明来源冲突，prompt 要求“矛盾时如实说明” | `ingest.py` `rag.py` |
| **图像识别**：游客拍照问“这是哪” | 多模态模型识图，**输出被约束在景点候选集内**（不在集合内则置 null，避免瞎编景点名），识别结果拼成检索问句进入同一条 RAG 链路；前端压缩到长边 1024 控制体积 | `rag.py` `index.html` |
| **服务可用性**：Embedding / 改写服务偶发失败 | 重试 + 降级：向量失败回退 BM25，改写失败回退原问题；整体不因单点失败而不可用 | `llm.py` `rag.py` |
| **公开演示的成本与滥用** | 按 IP 限流、问题长度与图片大小限制、无关问题不调用 LLM | `main.py` |
| **数据清洗** | 去 HTML、全角空白、爬取噪声行（版权/责编/广告），统一空行；来源与更新时间写入 front matter | `ingest.py` |

## 3. 评测

`eval/qa.jsonl` 含 22 条应命中的问题（包含别名、口语、多轮之外的常见问法）和 3 条应拒答的问题，用 hit@k / MRR / 拒答正确率衡量检索。

纯 BM25 基线（当前实测）：hit@1=0.77，hit@5=1.00，MRR=0.89，拒答 3/3。
开启向量后用 `python -m eval.run_eval` 与 `--bm25` 对比，可看到混合检索对口语问法的增益（见下方“结果”，部署后补充）。

> 评测集规模很小，只用于回归和消融，不代表线上真实分布。

## 4. 部署

**Render（推荐，免费 Docker）**：仓库推到 GitHub → Render 新建 Web Service（Blueprint 会读取 `render.yaml`）→ 在环境变量里填 `LLM_API_KEY`、`EMBED_API_KEY` → 部署完成后得到公开地址。
**Hugging Face Spaces（Docker）**：同一个 `Dockerfile`，端口设为 7860（`PORT=7860`），在 Space Secrets 里配置密钥。
注意：免费实例闲置会休眠，首次访问需等待数十秒；索引在首次启动时构建。

## 5. 已知局限

- 语料为人工整理的 5 个文档（约 40 个块），事实需在上线前对照官方资料复核，尤其是门票、开放时间、紫藤位置等。
- 识图依赖通用多模态模型，对相似建筑（如多个亭子）可能不准；高置信度与否已回传前端展示，但未做专门的景点图库检索。
- 未做重排（rerank）；块数量增大后可在 RRF 之后加交叉编码器或 LLM 重排。
